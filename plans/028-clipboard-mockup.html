Why it looks like this

  • Rows mirror Recent activity. Same 10px card, same hairline, same coral selection glass. A second list style would make the window feel like two apps stitched together.
  • Preview is one line, always. The store already truncates to 500 characters; the row truncates again visually. Multi-line rows turn a 250-item list into endless scrolling.
  • Images get a thumbnail, not a decoded preview. Dimensions come from image metadata rather than a full decode — the same reason the store reads them with CGImageSourceCopyPropertiesAtIndex.
  • Source app and time carry the identification load. "Which of these four URLs" is answered by where and when far more often than by the text itself.
  • Actions appear on hover only. Three buttons on 250 resting rows is visual noise; the selected row keeps them visible for keyboard use.
  • Both failure states are loud and specific. Amber says the data exists but can't be read; red says nothing is being captured. Neither is allowed to render as a plain empty list — that's the defect the audit caught.
  • Pin is drawn but not built. It is the one obvious escape hatch from a byte-budget eviction, and it needs a store field. Shown so the layout has room for it, not because it exists.
